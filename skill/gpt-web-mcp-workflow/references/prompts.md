# 可复用提示词模板

这些模板用于把网页端 ChatGPT 当作“规划大脑”。使用时把 `{...}` 占位替换为实际内容，通过 `ask_chatgpt(question)`（或底层 `chat_send`）发送。

## 1. 首轮身份声明（必做）

```
你是规划大脑：你是 ChatGPT Web 网页端的规划者。
我是本地执行者：我是运行在 Windows 主机工作台上的 Codex 代理，负责查环境、补环境、写脚本、建目录、跑验证。

本轮目标：{一句话目标}
请直接给规划本身，不要复述这段说明。要求覆盖：
1) 分阶段计划与每阶段验收标准；
2) 安全/隔离/回滚要求（如适用）；
3) 缺什么补什么的方法论（依赖探测→最小补装→记录版本→可复现）；
4) 测试矩阵与工具链；
5) 复杂目标的分析流水线（如适用）。
用中文输出，控制在 {900} 字以内，先给结论再给步骤。
```

## 2. 规划细化（把某阶段锁成可执行规格）

```
我是本地执行者，已收到你的规划。现在要动手做{阶段名}，请把该阶段锁成可直接执行的规格：
1) 目录/文件结构；
2) 最小工具或依赖清单与安装命令；
3) 验收命令或脚本入口；
4) 现实回退方案（若本机环境与假设不符）。
控制在 {700} 字以内，直接给规格。
```

## 3. 环境实测反馈 + 拍板

```
我是执行者，现汇报本机实测：{实测结果：版本/可用性/阻塞点}。
请据此拍板三件事（每点一句话）：
1) {决策点1}
2) {决策点2}
3) {决策点3}
```

## 4. 执行回报 + 裁决请求

```
执行者向大脑汇报{阶段名}完成情况：
- 完成项：{清单}
- 证据：{命令输出摘要 / 报告文件 / 数据}
- 偏差与原因：{如与计划不一致}

请裁决两件事：
1) 是否放行；放行则给下一阶段最小实施指令（{字数}字内）。
2) {需要修复或决策的问题}（{字数}字内）。
控制在 {300} 字以内。
```

## 5. 验收证据模板（执行者回报时用）

```
日期：{YYYY-MM-DD}
环境：{OS/版本}
链路：Bridge {版本} / 扩展 {版本} / 目标 {tab_id} / 页面 {url}
执行结果：
- {检查项1}：{结果}
- {检查项2}：{结果}
异常与截图位置：{路径或说明}
```

## 6. 新对话启动指令（把整个工作流交给新 Agent）

```
你是本地执行者。请先安装并阅读“GPT Web MCP工作流规范”skill（解压到 skills 目录，或直接按 SKILL.md 执行），
然后读取我提供的手写需求 {需求文件路径}。
按 skill 的工作循环开始：
1) 自检 Bridge/扩展/标签页（browser_status，缺失时启动 scripts/start_bridge.ps1 或托盘程序）；
2) 用首轮身份声明模板向网页端 ChatGPT（大脑）发送目标；
3) 按大脑规划逐阶段执行，缺什么补什么，每阶段回报证据并请求裁决；
4) 用户认可后输出最终交付说明。
遇到与计划冲突或环境不符时，回报偏差与替代方案，由大脑拍板，不要擅自改变目标。
```
