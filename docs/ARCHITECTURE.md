# AI-Web-MCP 架构

核心结构保持“网页 + 扩展 + 常驻 Bridge”。MCP 和 CLI 都是入口，调用共同的 Client 与任务队列；Skill 安装在本地 Agent，负责规范调用，不是额外服务。Windows EXE 只管理桥的生命周期和状态。

提供方注册层目前包含 ChatGPT、GLM。每个提供方负责：域名与历史 URL、会话 ID、页面就绪、输入与上传、发送确认、生成状态、最终回答及新会话。后续新增网页提供方扩展适配器与能力注册即可，不复制桥服务。

## 独立操作

1. 选择提供方与已有会话 URL，或新建聊天。
2. 获得 `target_id` 后，可以发送文字，或先上传图片。
3. 单独上传只放附件，不发送问题；后续发送显式使用附件。
4. 一次看图接口组合上传和发送，保留同样的目标、去重和错误规则。
5. 查询任务、取消、本地历史读取等不更换提供方或会话。

GLM 的历史身份来自 URL 的 `cid`；`t` 是时间参数。ChatGPT 历史身份来自 `/c/<id>`。不同目标不得默默串线；多个就绪目标没有明确选择时返回歧义错误。

## 网页与本地数据

网页模型在浏览器原账户中运行。扩展在目标页面上传文件、填写并发送提示，确认新用户消息上屏后等待新回答。GLM 适配器排除思考区，读取最终回答；ChatGPT 沿用现有页面适配器。

SQLite 保存桥采集的消息和任务状态。本地历史搜索不是云端账户全部聊天搜索。图片、原始 DOM 和实机验收只保留本机被忽略的数据目录，不随公开仓库发布。

## 名称迁移

正式品牌为 AI-Web-MCP，程序为 AI Web MCP，Python 模块为 `ai_web_mcp`，统一技能为 `ai-web-mcp`。旧 GPT 模块及工具保留兼容入口，旧调用不自动切到 GLM。
